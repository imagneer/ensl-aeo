# 엔슬 AEO MVP — 플랫폼별 예산 점검 로그

매주 월요일 자동 점검(scheduled task) + 예산 관련 사고 발생 시 수시 기록. 새 회차는 표 맨 아래에 행/섹션만 추가할 것 — 기존 행 삭제/수정 금지.

> **참고 (2026-09-04 병합 시 추가)**: 이 파일은 원래 Claude 프로젝트 지식에만 있었고 git 저장소에는 커밋된 적이 없었다. 그래서 2026-09-04 코난 작업 중 "기존 파일 없음"으로 판단해 8/31 기록 없이 새로 만드는 사고가 있었음 — 이번에 병합해서 바로잡음. **앞으로는 이 파일을 git 저장소에도 커밋해서, 다음에 코난이 같은 이름으로 다시 새로 만드는 일이 없게 할 것.**

## 배경
2026-08 말, OpenAI 비용이 PRD 예산($6/월 추정, gpt-5.6-luna 가정)보다 훨씬 많이 나가고 있는 걸 뒤늦게 발견함. 실제로는 `gpt-5-search-api`(검색 그라운딩을 항상 강제하는 검색 전용 모델) 사용 중이라 토큰비 + 웹서치 툴 콜 비용이 별도로 붙는 구조. 이건 버그가 아니라 측정 정확성을 위한 의도된 설계였지만, PRD 비용표가 이 변경을 반영하지 못해 예산과 실측치가 어긋났던 것. 이 계기로 매주 정기 점검 루틴을 만듦.

### 2026-09-04 — 예산 소진 사고 ($0.04 초과로 API 차단)

**발단**: Anthropic 크레딧 잔액이 -$0.04가 되면서 API 호출이 차단됨.

**원인 (코드로 확인 완료)**:
1. 2026-09-03에 배포한 "경쟁사 특징 추출 2단계" 확장으로 daily 집계당 LLM 호출이 최대 4배(타겟 1 + 경쟁사 최대 3) 늘어남 — 조합당 최대 72×4=288회(이전 최대 72회).
2. 2026-09-03 11:24~11:50 KST에 기존 504개 daily 행에 대한 일회성 백필(`backfillCompetitorKeywords`)을 5회 호출 — 내부적으로 604~738회 실제 LLM 호출 발생.
3. 그날 밤(UTC 9/3 15:30 = KST 9/4 00:30) 경쟁사 확장이 포함된 첫 `aggregate-daily` 자동 실행이 겹침 — 같은 UTC 날짜 버킷에 두 이벤트가 같이 잡힘.
4. `lib/keyword-extractor.ts`가 `data.usage`를 로그로 안 남기고 있어서, 사고 이후 정확한 토큰/비용을 사후 복원할 수 없었음.

**9/3 UTC 스파이크($3.03) 분해 (추정, 실측 아님)**:
- 평상시 하루 기본선 ≈ $0.6
- 백필 604~738회 × 건당 ≈ $0.002~0.003 ≈ **$1.5~2.2** (일회성)
- 첫 확장 크론 추가분 ≤216회 ≈ **$0.4~0.65** (매일 반복되는 고정비 증가)
- 합계 ≈ $2.5~3.4 → 실측 $3.03과 정합

**결론**: 백필이 그날 스파이크의 주범, 경쟁사 확장 크론은 앞으로의 고정비 증가(하루 최대 $0.4~0.65 수준 추정).

**조치 (작업지시서_LLM비용_안전장치_2026-09-04.md 기준, 코난 구현)**:
- `lib/llm-usage.ts` 신설 — ANTHROPIC_API_URL을 fetch하는 7곳(전부) 호출 usage를 구조화 로그로 기록(성공/실패 둘 다). `aggregate-daily` 실행 1회당 `llmCalls`/`llmCallsByKind`/토큰 합계를 응답·로그에 노출.
- `backfillCompetitorKeywords()`에 `?dryRun=1` 추정 모드 추가(실제 호출 없이 예상 건수·토큰·비용만 계산).
- `MAX_LLM_CALLS_PER_RUN=400`(`lib/llm-config.ts`) 상한 추가 — 크론 1회 실행이 이 상한을 넘으면 남은 조합을 중단하고 로그를 남김.
- 경쟁사 키워드 추출 기능 자체는 롤백하지 않음(Day21 브랜드 현 위치 화면이 이 데이터를 쓰고 있어 루아 결정 대기 — 작업지시서 "하지 말 것" 1번).

**미완료/후속 필요**:
- usage 로깅 코드 경로는 **가짜 fetch로만 검증**됐고, 실제 API 호출로는 아직 검증 안 됨(예산이 마이너스였던 시점이라 의도적으로 보류). 크레딧 충전 후 실제 호출 1회로 재검증할 것. **→ 검증 완료(2026-09-04, 코난)**: 크레딧 재충전 확인 후 `extractExpressionsFromParagraphs`를 문단 1개짜리 최소 호출로 실제 API에 1회 호출. 실측 `input_tokens=1405, output_tokens=61`, 구조화 로그(`{"llm_call":1,"status":"success",...}`) 정상 출력, 누적 집계도 정확히 갱신됨 확인. 비용은 대략 $0.0017(오차 감안해도 1센트 미만). 이 실측치로 `ESTIMATED_TOKENS_PER_KEYWORD_CALL`의 입력 토큰 추정을 900→1200으로 상향 조정함(9/3 역산 추정이 tool_choice 스키마 오버헤드를 과소평가했던 것으로 보임, n=1이라 여전히 대략치).
- dry-run 비용 추정 로직은 이번엔 처리 대상이 0건이라(이미 백필 완료 상태) 실제 계산이 수행된 적이 없음 — 처리할 항목이 생겼을 때 숫자가 말이 되는지 한 번 더 확인 필요.
- Supabase `llm_calls` 테이블(조회 가능한 usage 이력 저장)은 이번엔 선택 항목으로 스킵함 — 그래서 dry-run 추정치는 역산 대략치이지 실측 평균이 아니다. 필요해지면 추가할 것.
- `lib/brand-one-liner.ts`(Sonnet 5, 진단 종료 시 1회)는 최근 30일 콘솔 비용에 아직 안 잡혀 있음 — 진단이 처음 종료되는 날 새 비용이 튈 예정, PRD 예산에 미반영 상태(에일 진행 예정).
