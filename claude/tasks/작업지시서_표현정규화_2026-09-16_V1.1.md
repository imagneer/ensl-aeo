## 왜 (배경)

"인지와 추천의 서사" 화면의 TOP10 비교(소개 특징 vs 추천 표현)에서, 초록색 하이라이트가 실제 개념 일치를 정확히 반영하지 못하는 문제가 발견됨.

**사실 확인됨 (스크린샷 원본 대조 완료)**:
- **과다 집계**: 왼쪽 "위치"(1위), "365일 연중무휴 진료"(4위)가 오른쪽에서 각각 복합 문구(1위: "화곡역 1분 거리에서 365일 진료")와 단독 문구(3위, 5위)로 쪼개져 두 자리씩 차지함 → 겹치는 실제 개념 수(2~3개)보다 하이라이트 개수(좌 3 / 우 4)가 부풀려 보임
- **과소 집계**: 오른쪽 4위 "일요일 진료"는 왼쪽 "365일 연중무휴 진료"와 같은 상위 개념(진료 시간)인데 지금은 하이라이트 안 됨

**가설이 구체화됨 (루아 설명, 코난 코드 확인 아직 필요)**:
- 왼쪽 '소개 특징'은 원자 표현(예: 강서구/화곡동/화곡역 인근)을 AI가 의미별로 묶고 새 요약 이름을 붙인 **가공 후** 결과
- 오른쪽 '추천 표현'은 별도로 묶거나 정규화하지 않고, 원문에 가까운 단위로 빈도만 센 **가공 전** 결과
- 즉 "서로 다른 기준"이 아니라 "서로 다른 처리 단계"를 비교하고 있었던 것 — Day12(키워드 추출)·Day22(브랜드 한 줄·인지 특징 생성) 기록과 방향이 일치함. 코드/프롬프트로 최종 확인만 남음.

**연결되는 다른 작업**: 이 문제는 별도로 논의 중인 "소개-추천 공통 특징 1개를 히어로에 쓰자"는 계획의 선행 조건임. 정규화 없이 그 계획부터 실행하면 같은 이중 집계 버그를 그대로 상속함.

## 무엇을

1. TOP10끼리 순위로 비교하는 방식을 버리고, "소개에서 나타난 핵심 개념이 추천 답변 전체(220건)에서 얼마나 나타나는지"를 비교하는 방식으로 전환
2. 이를 위해 원문 표현을 원자 단위로 분해한 뒤 상위 개념으로 묶는 정규화 레이어 추가

## 어떻게

### 1단계 — 원인 확인 (코딩 전, 범위 좁혀짐)
아래 두 가정만 코드/프롬프트로 확인:
1. '소개 특징' 19개가 실제로 AI 클러스터링+명명 단계를 거친 결과가 맞는지
2. '추천 표현' TOP10이 실제로 정규화 없이 원문 근접 표현의 빈도 집계가 맞는지

둘 다 맞으면(유력한 시나리오) 2단계로 진행. 예상과 다르면 원인부터 재조사.

### 2단계 — 정규화 방식: 새 카테고리 설계 대신 기존 클러스터에 매칭 (우선 검토)
노바가 제안한 5개 카테고리를 처음부터 새로 만들어 양쪽에 적용하는 대신, **이미 정리(일부는 사람 검증)된 왼쪽 소개 특징 19개 클러스터를 기준(canon)으로 삼아 오른쪽 원문 표현을 거기 매칭**하는 방향을 우선 검토:

- 오른쪽 220건 원문에서 나온 표현들을, 왼쪽에 이미 있는 19개 특징 클러스터 중 하나에 속하는지 먼저 판정 (예: '화곡역 1분 거리' → 왼쪽 '강서구 화곡동/화곡역 인근 위치' 클러스터에 매칭)
- 어느 기존 클러스터에도 안 맞는 표현만 새 클러스터로 분리 — 이 경우에만 새 이름 부여 필요 (노바의 5개 카테고리는 이때 참고 후보로 남겨둠)
- 장점: 왼쪽은 다시 손댈 필요 없음, "같은 개념은 어디서나 같은 이름" 원칙이 왼쪽 이름을 그대로 쓰는 것만으로 자동 충족됨
- 위험: 왼쪽 클러스터링은 '인지 질문'(소개) 맥락으로 튜닝된 로직이라, '자리 질문'(추천) 답변 표현에 그대로 적용하면 맥락 차이로 매칭이 안 되거나 부정확할 수 있음 — 실제로 돌려보면서 확인 필요

만약 이 방식이 잘 안 맞으면(위 위험이 실제로 크면), 노바 방식(양쪽 다 새 카테고리로 재분류)으로 대체.

### 3단계 — 판정 로직
기존 파이프라인 재사용: Haiku 1차 카테고리 판정 → 애매한 경우(카테고리 간 걸치는 표현)만 Sonnet 재검수. `reason_stated` 판정 때와 같은 구조. 새 판정 규칙을 처음부터 만들지 않고 기존 구조를 확장하는 방향.

### 4단계 — 사람 검증
카테고리 매핑 결과도 기존 세 화면과 동일하게 사람 검증 큐 대상 (특히 새 브랜드에 처음 적용할 때는 필수). 카테고리로 묶더라도 각 항목은 항상 원본 답변 원문과 연결 유지.

### 5단계 — 화면 반영
TOP10 좌우 대조를 "카테고리별 소개 강도 vs 추천 등장 비율" 비교로 교체. 비율 표기 시 분모 항상 함께 표시.
